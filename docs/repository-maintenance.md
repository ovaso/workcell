# Repository Maintenance

## Sources of truth

`workcell` is the product source repository. The following root-level content is maintained manually:

- `docs/`
- `specs/`
- `schemas/`
- `facts/`
- Bootstrap-specific protocols and scripts under `skills/bootstrap-workcell`
- workspace assets under `skills/bootstrap-workcell/assets/workspace-v0.1` that are not synchronized from another source

The following directories are generated by `scripts/build-bootstrap-assets.sh` or its PowerShell counterpart `scripts/build-bootstrap-assets.ps1` and must not be edited directly:

- Bootstrap `references/specs/`
- Bootstrap `references/schemas/`
- Bootstrap `references/product-docs/`
- Bootstrap `references/product-facts/`
- workspace asset `.ai-workspace/specs/`
- workspace asset `.ai-workspace/schemas/`
- workspace asset `docs/workcell/`
- workspace asset `knowledge/tool-capabilities.toml`
- workspace asset `.ai-workspace/release-manifest.json`
- Bootstrap `checksums/workspace-v0.1.sha256`
- workspace asset `LICENSE`

Synchronization uses release allowlists. `references/product-docs/` carries only generic product documentation, while `references/product-facts/` carries only reusable decisions and seed knowledge. `docs/session-summary.md` is source-repository design history and must not enter the Skill ZIP or expanded workspace.

## Local validation

```text
scripts/build-bootstrap-assets.sh
tests/run.sh

# PowerShell
& ./scripts/build-bootstrap-assets.ps1
& ./tests/run.ps1
```

The source-repository maintenance baseline is either POSIX `sh` or Windows PowerShell 5.1/PowerShell 7, plus Python 3.11+ and Node.js. POSIX packaging uses `zip`; PowerShell packaging uses native .NET ZIP APIs and includes dot-prefixed release content explicitly. These are product-maintenance tools, not default requirements for a new workspace or Bootstrap expansion target.

Validation must remain offline, install no dependencies, avoid modifying the parent workspace, and produce no Python cache. Tests cover schema examples, TOML mappings, runtime scripts, Skill metadata, Bootstrap creation into an empty directory, refusal of non-empty targets, distribution drift, Doctor behavior, and ZIP integrity.

## Version synchronization

Before release, verify all of the following together:

- `VERSION`
- `product.toml`
- Bootstrap `bundle.toml`
- workspace `.ai-workspace/workspace.toml`
- workspace `.ai-workspace/versions.lock`
- every schema and API version
- `CHANGELOG.md`

Change versions in root sources of truth first, then rebuild the self-contained Skill. Never change only a synchronized copy.

## Packaging

```text
scripts/package-bootstrap-skill.sh

# PowerShell
& ./scripts/package-bootstrap-skill.ps1
```

Artifacts are written to `dist/` by default and include the Skill ZIP and its SHA-256 file. The ZIP is the formal distribution candidate; the Git repository remains the source-maintenance form.

## Release gates

Before every public release:

1. Verify that `LICENSE` and `product.toml` both declare MIT licensing.
2. Verify that the canonical origin is `https://github.com/ovaso/workcell`.
3. Build from an immutable tag.
4. Run the complete test suite.
5. Verify GitHub workflows, issue forms, Dependabot, and repository security settings.
6. Verify that no credentials, host-specific absolute paths, caches, binaries, or non-English canonical content are present.
7. Verify the ZIP SHA-256.
8. Confirm self-update remains disabled unless its independent security protocol is complete.

This repository must not commit, push, tag, or publish automatically.
